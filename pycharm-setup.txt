==============================================================
GameBasic in PyCharm einrichten
==============================================================

1) PROJEKT-INTERPRETER AUF DIE .venv UMSTELLEN
----------------------------------------------
File -> Settings -> Project: GameBasic -> Python Interpreter
Zahnrad oben rechts -> "Add Interpreter" -> "Add Local Interpreter"
-> "Existing" -> Pfad waehlen:
    C:\Programmieren\Python\GameBasic\.venv\Scripts\python.exe
Bestaetigen. PyCharm sieht jetzt pygame und alle anderen Pakete.


2) RUN-KONFIGURATION FUER dhrun.py
----------------------------------
Rechtsklick auf dhrun.py -> "Modify Run Configuration..."
oder oben rechts -> "Edit Configurations..." -> "+ Python".

Name:               Pong (oder beliebig)
Script path:        C:\Programmieren\Python\GameBasic\dhrun.py
Parameters:         examples/10_pong.dh
Working directory:  C:\Programmieren\Python\GameBasic
Python Interpreter: Project Default (.venv)

Das gleiche kannst du fuer 09_shapes, 12_sprite, 13_sound usw.
duplizieren.


3) WENN PYCHARM NUR DIE EINZELDATEI ZEIGT
-----------------------------------------
Falls du bisher nur dhrun.py geoeffnet hast (kein Projektbaum):
  File -> Close Project
  File -> Open... -> ORDNER C:\Programmieren\Python\GameBasic auswaehlen
  -> "Trust Project"

Links das Projekt-Tool-Fenster mit Alt+1 einblenden.
Du siehst dann die Struktur:
  GameBasic/
    .venv/                  <- PyCharm verbirgt das oft, ist normal
    examples/
      assets/
      *.dh
    drachenhauch/              <- das ist das Python-Paket
      *.py
    dhrun.py
    pyproject.toml

5) STARTEN OHNE PYCHARM
-----------------------
Aus jedem Terminal im Projekt-Ordner:

    gb.cmd examples\10_pong.dh           (Windows-CMD/PowerShell)
    ./gb.sh examples/10_pong.dh          (Git-Bash, WSL)

beide nutzen automatisch den .venv-Python und brauchen nichts global.


6) SPIELE ALS .EXE VERTEILEN
----------------------------
Voraussetzung: native VM ist gebaut (dh-build.cmd).

    dh-package examples\10_pong.dh --windowed --onefile
        -> dist\10_pong.exe (etwa 17 MB, einzelne Datei)

    dh-package examples\17_tilemap.dh --windowed
        -> dist\17_tilemap\17_tilemap.exe (Ordner mit allen DLLs,
           etwa 40 MB, schneller Start)

Optionen:
    --windowed     Kein Konsolenfenster (Release-Modus). Ohne diese Option
                   kommt eine Konsole mit, was beim Debuggen hilft.
    --onefile      Eine einzige .exe statt eines Ordners. Startet etwas
                   langsamer (extrahiert beim Start in den Temp-Ordner),
                   aber simpler zu verteilen.
    --icon=mein.ico  Eigenes Icon fuer die .exe.
    --name=Sonic     Eigener Name (sonst aus Dateiname abgeleitet).
    --clean        Loescht alte Build-Artefakte vorher.

Verteilen:
- Bei --onefile: nur die .exe-Datei kopieren. Die assets/ liegen drin.
- Bei Ordner-Build: den ganzen Ordner aus dist/<name>/ verschicken
  (z.B. zippen).

Sicherheitshinweis: Manche Antivirus-Programme melden PyInstaller-.exes
als verdaechtig (False Positive). Wenn das stoert, mit Microsoft Defender
ausschliessen oder die .exe signieren.
